## Codebase Patterns

- **Event stream structure**: harness_start → [text, repl_input, repl_progress*M, repl_output]*N → harness_end
- **Graph copying is the bottleneck**: `addNode`, `addEdge`, `extendEdge` all create new Map copies via `new Map(existing)`. `reduceEvent` copies 11 Maps in ReducerState per event.
- **defaultActive iterates all nodes+edges**: Called after every event in `reduceConversation`, iterates all nodes to find messages, then all edges for summaries.
- **projectRepl does full graph re-walk**: `collectRunChunks` iterates ALL nodes to find start chunk for each runId. `collectRunIds` also iterates all nodes.
- **Import paths**: From `__tests__/perf/`, server-event is at `../../../server-event`, types/primitives/reducer at `../../<name>`, sidebar at `../../../../../../packages/ui/cli/repl/sidebar`

## 2026-03-03 - P0
- Created event stream generators (`generators.ts`) parameterizable by (turns, progressChunksPerTurn, numRuns)
- Created timing harness (`timing.ts`) with benchReduceEvent, benchReduceConversation, benchProjectRepl, benchFullPipeline
- Created 13 benchmark tests covering generator correctness, timing harness validation, and baseline measurements
- Files: `packages/ai/client/hypergraph/__tests__/perf/{generators,timing,benchmark.test}.ts`
- Results: All 13 tests pass, all 208 existing tests pass
- **Learnings for future iterations:**
  - The immutable Map copying pattern in primitives.ts (addNode/addEdge/extendEdge) is the core cost driver — each creates new Maps
  - reduceEvent copies 11 Maps per event (ReducerState) even when most don't change
  - defaultActive in walk.ts iterates all nodes to find messages — linear with graph size
  - projectRepl's collectRunChunks iterates ALL graph nodes per runId to find start chunk — O(nodes * runs)
  - flattenAgents is a simple recursive tree walk — unlikely to be the bottleneck compared to reduce/project
- **Mutable primitives pattern**: `addNodeMut`/`addEdgeMut`/`extendEdgeMut` mutate in place for O(1) per call. Use in hot paths where caller owns the graph. Keep immutable variants for operations.ts and tests.
- **Incremental active set**: Track `messageCounter` before/after `reduceEvent`, add only new `msg:N` IDs. Avoids O(N) `defaultActive` scan.
- **Spawn edge check**: Must capture `isFirstEventForRun = !state.lastChunkByRunId.has(runId)` BEFORE any state mutations, since `lastChunkByRunId.set()` happens early in the function.

## 2026-03-03 - P1
- Eliminated O(N^2) scaling in reduceEvent by mutating graph in place instead of copying Maps
- Added mutable primitive variants: addNodeMut, addEdgeMut, extendEdgeMut
- Replaced defaultActive (O(N) per call) with incremental updateActive (O(1))
- Files: `primitives.ts`, `reducer.ts`, `conversation.ts`, `reducer.test.ts`, `p1-sublinear.test.ts`
- Benchmark results:
  - reduceEvent @5300 events: degradation 9x → 0.35x
  - reduceConversation @5300 events: degradation 12x → 0.46x
  - reduceEvent @20600 events: degradation 31x → 0.33x
  - reduceConversation @20600 events: degradation 23x → 0.54x
  - Total time @20600 events: ~10s → 15ms
- **Learnings for future iterations:**
  - Mutating in place is safe when all callers immediately reassign: `[g, s] = reduceEvent(g, s, e)`
  - Must capture pre-mutation state values before any writes for later checks (spawn edge condition)
  - Need new object reference for Solid.js reactivity: `{ ...state, graph, reducerState }`
  - The bottleneck was Map copying, not algorithm complexity — reducing from N copies to 0 per event was the key
